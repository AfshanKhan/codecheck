# What's actually verified vs. what's expected to work

"Built on the same code path as X" is not the same as "tested." Two providers
already claiming OpenAI compatibility (LM Studio, Ollama) both turned out to
have real quirks once actually tested live (see Tiers 2 and 3 in [Architecture](Architecture.md)) — so
nothing in this table is marked ✅ unless it was run against a real, live
instance and produced a real result, not just passed a mocked unit test.

CodeRabbit then found 8 further real bugs on the same PR, each reproduced live against the actual code *before* fixing (not just accepted on the bot's word): `RULE-035` never read a nested `.gitignore` a few directories down from repo root at all (only the root one); `RULE-024`/`RULE-026` misattributed a call inside a *nested* function/lambda's deferred body as running immediately (a `.save()` in a callback merely *defined*, not called, inside a loop; conversely, `RULE-024`/`RULE-025` missed a blocking call sitting in a nested function's *default-value expression*, which genuinely does run immediately, unlike its body); `RULE-034` and `RULE-023` anchored their diff-scope check on the wrong line (the `def`/`fieldname` line instead of the actual changed default value's own line, same class of gap as the earlier `RULE-018`/`RULE-015` fixes); `RULE-021` didn't recognize an annotated `override_doctype_class: dict = {...}` assignment; `RULE-032` incorrectly treated `settings.limit = total * 4837` as a constant declaration due to an `all()`-over-an-empty-generator bug once non-`Name` targets were filtered out first. All 8 confirmed with a before/after repro, fixed, and covered by new/updated tests. The `RULE-026` fix (skip a nested function's *body*, but not its decorators/defaults, when it's defined inside a loop) initially introduced a real regression of its own, caught only by re-running the live fixture audit, not by any unit test: the skip was applied unconditionally rather than only once already inside a loop, and since a top-level method is itself "a nested function" relative to its enclosing class, that silently broke finding an ordinary, non-deferred `.save()` inside a `for` loop nested in a method at all — every existing unit test used a bare loop with no enclosing function, so none of them exercised this shape. Fixed by scoping the skip to `next_depth > 0` (already inside an active loop) instead of applying it everywhere, with a new regression test for exactly this nested-in-a-method shape. |
